## 0. ZERO-HARDCODING RULE (highest priority — applies to the whole codebase)
Nothing that describes the patient, the model, the anatomy or the results may be hardcoded in the frontend or backend code.
Every value must come, at runtime, from one of these sources of truth:

| What | Single source of truth |
|---|---|
| Input fields: names, labels, groups, types, units, min/max, steps, defaults, help text, normal ranges, modifiable flags | `GET /api/schema` (built from `artifacts/feature_schema.json` + `reference_ranges.py`) |
| Probabilities, labels, risk tier, expected vessels, SHAP contributions, group contributions, warnings, summary text | `POST /api/predict` (the live model) |
| What-if deltas, sensitivity curves | `POST /api/what-if`, `POST /api/sensitivity` (the live model) |
| Thresholds, risk-tier cut-offs, reliability badges, metrics, CIs, limitations | `GET /api/model-card` (from thresholds.json / metrics.json / ML_SUMMARY.md) |
| Mesh names, vessel keys, anchors, view presets, body regions, region↔feature mapping, colours, colour scale, opacities, pulse rates, tooltips, modifiable list | `GET /api/anatomy-map` + the `scene` field of /api/predict |
| Sample patients | `GET /api/examples` (selected from split.json at runtime) |
| Disclaimer, attributions, dataset citation | API (config.DISCLAIMER, anatomy_map.asset.sources, model-card) |
| Viewer look (background, lights, HDRI, tone mapping) | `artifacts/viewer_look.json`, served via the API or synced at build time from that file only |
| Feature-effect meters | `artifacts/feature_response.json`, generated by the audit script (section 1.4) |

## 2. Make every change VISIBLE (honest, model-driven)
When any input changes and the new prediction arrives:

**a. Change toast on the canvas** (top-centre, 2.5 s, non-blocking):
"<feature label> → <new value>: CAD +3 pts · LAD +5 · LCX +1 · RCA +2" — with ↑ / ↓ arrows. The label and values come from the schema and the API delta (new − previous response).
If |Δ| < 0.5 pts for all targets: "<label> → <value>: little effect on this model's estimate (see Model card → feature effects)."

**b. Vessel change flash:** each vessel whose probability changed ≥ 1 pt does one soft emissive flash (300 ms) and gets a floating chip at its anchor (from anatomy_map), "+5 pts" / "−3 pts", that fades after 2 s.

**c. Heart tier transition:** if the risk tier changes, cross-fade the myocardium tint over 600 ms (tint values from anatomy_map heart_tiers), show a tier-change chip, and update the heartbeat amplitude.

**d. Body-region link:** look up the changed feature in anatomy_map body_regions — do not hardcode the mapping. Briefly pulse that organ (in body mode) or show a small region chip in heart mode ("<region display_name> ↑/↓" with the API's region direction).
- Example (smoking): the region is looked up from the map → the lungs glow + a chip "<region display_name>: contributing risk factor".
- The tooltip text comes from `anatomy_map.region_tooltip`: "location of a contributing risk factor — NOT the location of disease".

**e. "What changed" panel** (right panel, collapsible, under Risk summary): the last 5 changes, each as feature old → new with Δ per target (from the API responses). Clicking one reverts it.

**f. Input-side effect meter:** next to each field, a tiny 0–3 bar meter from `feature_response.json` (served via /api/schema as `effect_strength`). Tooltip: "How much this input can change this model's estimates."
